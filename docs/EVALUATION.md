# 早期验证记录

本记录使用虚构对话。样本很小，只能验证特定路径，不能据此判断长期准确率、可靠性或成本优势。

## 标准 AstrBot 安装验证

- 未修改的 AstrBot 源码：`abf6830`，版本 4.29.3；候选插件位于独立数据目录。
- 假 OneBot 反向 WebSocket，测试账号均为虚构值；不连接 QQ，不读取真实用户的数据库。
- 使用同一 DeepSeek 聊天模型：明确要求保存饮品偏好，核对工具调用和 SQLite 数据；清空会话并要求查找，确认返回；`/我的记忆`列出记录。重启 AstrBot 后列表仍能看到该记录。
- 测试时发现模型偶尔省略了事实检索的可选类别参数，导致一次工具调用报错；候选版本已为可选参数添加默认值。重启标准 AstrBot、清空对话后，实测模型使用空参数调用该工具并成功取回事实；工具级测试也覆盖省略参数。

## 两个插件的小规模对照

- 一次试运行，使用相同 DeepSeek 聊天模型、两个独立 AstrBot 数据目录和同一模拟 OneBot 事件序列；LivingMemory 2.8.2 使用本地 Ollama `bge-m3`，未启用 Rerank。测试内容均为合成事实，不读取原实例的数据。
- 先明确要求记住“最喜欢陈皮气泡水”“不吃芹菜”，通过 `/reset` 清空当前对话上下文，再提问饮料和忌口；另询问从未提供的颜色。
- 两边在这一轮中都调用了记忆写入能力，清空上下文后均回答出两条事实，也都对未知颜色表示不知道。LivingMemory 的两次召回日志显示注入了两条记忆；结构化插件的工具查询结果按类别返回。
- 此轮结构化插件的首次保存响应约 2.39 秒、LivingMemory 约 9.51 秒；后者包括本地嵌入模型可能的冷启动，网络和模型生成时间也不受控。**不能据此比较长期延迟或成本。**
- 工具层还使用 8 条人工构造查询与“原文包含关键词”的简单基线比较。结构化字段由实验者直接提供，6 条可回答查询中精确字段命中 5 条，1 条同义属性漏查；基线命中 2 条。两条隔离/无答案样例均未返回。样本刻意展示精确结构化查询的适用情形，不能代表真实问答，也不构成与 LivingMemory 的对比。

复现：`python tests/test_store.py`、`python tests/test_tools.py`、`python tests/evaluate_lookup.py`。双插件对照可运行 `python tests/compare_plugins.py`，需要预先准备两个空数据目录的 AstrBot 4.29.3 实例：分别安装本插件和 LivingMemory 2.8.2，使用同一个聊天模型，开启 OneBot v11 反向 WebSocket 并只监听本机的 `6399` 和 `6499` 端口；在两个实例的白名单中允许 `memory-test:FriendMessage:203`，平台 ID 均设置为 `memory-test`。LivingMemory 配置本地 Ollama `bge-m3`、session 作用域、Rerank 关闭；脚本需要 `websockets`。脚本模拟 QQ、调用真实聊天 API 并产生费用，结果写入脚本旁的 `comparison-results.json`；它会执行 `/reset`，所以**仅能对隔离测试实例运行**，不应连接真实 QQ 或使用真实记忆数据库。模型输出和耗时会变化，重新运行前应使用新的测试数据目录以避免先前事实影响结果。

## 尚未验证

大规模和长期运行、更多模型/版本、跨平台与群聊真实对话、自动事实抽取精度、召回准确率/延迟/成本统计、隐私攻击与并发压力、SQLite 备份恢复、自动提醒，以及不同生命周期方案的用户体验。当前没有任何足以证明本插件优于其他插件的结果。
